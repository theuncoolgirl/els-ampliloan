## Fixed decisions
- Phase 1 file names differ from the contract's `implementation_location` values (for example `src/pages/ApplyPage.tsx`, `src/state/store.ts`). Treat those values as advisory. Keep all state-changing logic in the Phase 1 store actions, and emit events from the store actions or the page that owns the trigger, whichever matches the contract trigger text.
- Stable ID: the Phase 1 `anonymousId` is the app-owned browser ID. Reuse it. Do not create a second browser ID. Known ID: the synthetic `profileId`. Both must be set on the Amplitude client (`deviceId`, `userId`) before the first dependent event.
- Profile traits use the brief's values, as now written in `docs/custom-events.yml`: `customer_relationship` prospect/existing_customer; `borrowing_experience` first_time/experienced/unknown; `employment_type` employed/self_employed/business_owner/unknown. Persona traits: first_time_personal = prospect, first_time, employed, first touch paid_search; returning_mortgage = prospect, experienced, employed, email; business_owner = prospect, experienced, business_owner, partner; existing_customer = existing_customer, experienced, employment_type unknown, direct. An anonymous visitor with no persona has `customer_relationship=prospect`, `borrowing_experience=unknown`, `employment_type=unknown`.
- Attribution allowlist (everything else becomes `unknown`; never copy a raw query value). Landing format is `/els-ampliloan/?utm_source=…&utm_medium=…&utm_campaign=…#/` and must be read before any hash navigation. Sources: `google`, `bing`, `newsletter`, `partner_hub`. Mediums: `cpc`, `email`, `referral`. Campaigns: `spring_rates`, `first_loan_guide`, `partner_launch`. Channel derives from the pair: cpc → `paid_search`, email → `email`, referral → `partner`, none present → `direct`, present but not allowlisted → `unknown`. First touch is set once per browser lifecycle (user property `acquisition_channel_first_touch` via setOnce); session touch is captured per app session (30 minutes inactivity) and survives hash navigation.
- Persona fixtures that seed an application emit no business event for the seed. Loading a persona with a fixed profile emits `Signed In`; the anonymous personas emit nothing. Explicit sign-in, sign-up, and sign-out emit `Signed In`, `Sign Up Completed`, and `Signed Out` per the contract, and `Signed Out` is sent under the old identity before it is cleared.
- Application Submitted: persist first, then emit exactly one event per application ID, even with rapid double submit or two tabs. `Application Step Completed` is forbidden and must not exist anywhere.
- No arbitrary form values, URLs, free text, or document content in any property.
