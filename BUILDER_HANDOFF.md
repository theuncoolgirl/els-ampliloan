Log the installed version and check typings for: client creation and initialization (sync and async), `updateUserAsync`, user object (`userID`, `customIDs.stableID`, `custom`, no `privateAttributes` for analysis dimensions), `getParameterStore` and its typed getters, `getFeatureGate`, `getDynamicConfig`, `getLayer`, `logEvent`, and options to avoid auto exposure. - One client per page load, created lazily at module level (safe under React strict mode). Environment tier: do not set one (SDK default); record what the SDK reports as its default.
- User object from the single shared profile (Phase 2): `userID` = known synthetic profile ID when signed in (omit when anonymous), `customIDs.stableID` = the Phase 1 `anonymousId`, `custom` = the profile traits from `docs/custom-events.yml` `user_properties` (current brief values) plus first-touch and session-touch attribution fields, plus `traffic_type`. Stable ID does not change on sign-in. Sign-out rotates it, as in Phase 2. After any profile change, build a new user object and `await updateUserAsync` before any dependent evaluation. Each profile change increments a generation token; responses from older tokens are ignored; nothing evaluated for one generation is ever returned for another.
- Initialization waits at most 2000 ms; the UI continues on typed defaults; late completion never changes a visible value mid-step; retry evaluation only at a safe route boundary.
- Entity names and defaults (code must match exactly; none exist in the console yet):
